  THE SHORT PATH
Show up. Do good. Keep agency.

    
  1. Explore freely. Demo trails work without a wallet. Verify real-world access and safety yourself.
  2. Agree on the mission. Ask an organizer what evidence they accept. Send any registration or sensitive evidence privately through an agreed channel; this app has no public registration form.
  3. Organizer review comes first. Only the deployed contract’s owner can approve a particular wallet, location, token and amount. GPS, tutorials, saved trails and issue assignments do not create eligibility.
  4. Check, then claim. Base configuration, sponsor funds, allocation and your exact on-chain approval must exist. A submitted transaction is not a paid claim; wait for its successful receipt.

    
Development work & payroll
Link acceptance evidence in the agreed public issue, omitting private data. A maintainer-approved bounty label and private registration are prerequisites, not guarantees. The empty payroll pipeline remains steward-disabled. Only verified canonical Base PayrollPaid receipts settle queue entries.

    
Organizer lifecycle & unused funds
The left ankh requires verified on-chain owner permission. Pause a location to prevent new claims, cancel pending approvals individually, then release unused allocation only when no approvals remain for that location/asset. Recover only unallocated funds to an explicitly reviewed recipient; recovery is not a participant reward and never triggers claim celebration. Even the owner must explicitly allowlist their own address before sponsor funding. The IPFS header accurately reports unconfigured, local files only; no provider credentials, uploads or community pin actions are offered.

  LEFT ANKH · AUTHORIZED ACTIONS
Organizer & sponsor desk
Connect a wallet and explicitly read a configured Base deployment. No permission is inferred from this menu.

    
The contract owner organizes and allowlists sponsors. All writes require wallet confirmation, correct Base chain and successful receipts. Native ETH uses 18 decimals and needs no token allowance; USDC and other ERC20s use their individually verified decimals and a separate exact allowance.

    
Add USDC or another ERC20 to this desk
No USDC address is guessed. This explicit read verifies code and on-chain decimals, then adds the token only to this page. It is not an endorsement, funding or reward approval.

Owner: approve a reviewed participant
Approve only after private registration and evidence review. Location permission never approves a claim.

      
Owner: pause or reactivate a location
Deactivation prevents claims and new allocations; it does not cancel existing approvals or release funds. Review and cancel approvals separately.

      
Owner: release unused allocation
First cancel every pending approval for this location/asset. The contract refuses release while any approval remains. Release returns unused allocation to unallocated contract funds; it is not a wallet payment.

      
Owner: recover unallocated funds
Allocated funds cannot be recovered. Cancel approvals and release unused allocations first where needed. ETH uses wei precision; ERC20 decimals are verified individually.
